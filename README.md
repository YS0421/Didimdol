# didimdol-ai

[디딤돌](https://didimdol.cloud)의 AI 분석 엔진이에요. 이공계 학부생이 **과학기술 출연연 인턴**을 준비하도록 돕습니다.

> **핵심 원칙: 남과 비교하지 않는다.**
> 모든 수치는 ① 내가 정한 목표가 요구하는 수준, ② 지난주의 나, 이 두 가지만 기준으로 계산해요.
> 백분위, 순위, 평균 비교는 어디에도 없고, 코드로 검사해 막아요.

이 엔진이 하는 일:

1. 출연연 13곳의 채용 게시판에서 인턴 공고를 모으고, 첨부(PDF·HWP 등)에서 글을 뽑아요.
2. Claude가 공고에서 직무별 **요구 항목**을 원문 인용과 함께 정리해요.
3. 사용자의 **경험 카드**가 각 요구 항목을 얼마나 증명하는지 판정해요.
4. 고정된 **6축 육각형**, 갭 우선순위, "다음 한 칸" 행동, 칭찬·격려·채찍질 피드백을 계산해요.
5. 공고 직무를 추천하고(NCS 연결 포함), 주간·월간 리포트를 HTML이나 JSON으로 만들어요.
6. 이 모든 기능을 G7(그누보드7) `sirsoft-jobfit` 모듈이 호출할 **API 서버**로 제공해요.

## 빠른 시작

```bash
git clone https://github.com/YS0421/Didimdol.git
cd Didimdol
pip install -r requirements.txt
cp .env.example .env            # 키 입력 (아래 '키 설정' 참고)
python -m unittest              # 테스트 122개 (실제 API 호출 없음)
python -m didimdol_ai.simulate  # 가상 학생 5명 × 8주 원칙 검증
```

> **저장소에 없는 것:** `.env`(API 키)와 `collector_data/`(수집 DB, 공고 첨부 원본, 로그, NCS 원본 CSV)는 올리지 않았어요.
> 첨부 원본은 기관 자료라 다시 배포하지 않아요.
> 공고 DB가 필요한 기능(추천, 공고 API, `scripts/make_examples.py`)을 쓰려면 먼저 수집과 추출을 실행하세요.
>
> ```bash
> python -m didimdol_ai.collector run --pages 2
> python -m didimdol_ai.llm extract
> ```
>
> 테스트, 시뮬레이션, 데모 리포트는 DB 없이도 돌아가요.
> `data/examples/`에는 미리 만든 결과가 들어 있어요.

| 해 볼 것 | 명령 | 비용 |
|---|---|---|
| 공고 수집 | `python -m didimdol_ai.collector run --pages 2` | 무료 |
| 공고 요구 항목 추출 | `python -m didimdol_ai.llm extract` | Claude |
| 추천 보기 | `python -m didimdol_ai recommend` | 무료 |
| 데모 리포트 | `python -m didimdol_ai report --kind monthly --out reports/demo_monthly.html` | 무료 |
| API 서버 | `uvicorn didimdol_ai.api:app --host 127.0.0.1 --port 8000` | 요청에 따라 |

- **필요 환경:** Python 3.12
- **표준 라이브러리만 쓰는 부분:** 점수 계산, 추천, 지표, 리포트
- **추가 패키지가 필요한 부분:** 수집기는 requests, lxml, olefile, pypdf가 필요하고, Claude 연동은 anthropic, API 서버는 fastapi, uvicorn, python-multipart가 필요해요.
- **참고:** 이 PC에서는 `anthropic` 패키지를 불러오는 데 30초 넘게 걸려요. 그래서 API를 쓰지 않는 기능은 이 패키지를 불러오지 않게 했어요(지연 import).

### 키 설정 (`.env`)

키는 코드나 다른 파일에 넣지 않아요. `.env`는 `.gitignore`에 있어서 깃에 올라가지 않아요.

```
ANTHROPIC_API_KEY=...                 # Claude API 키
DIDIMDOL_LLM_MODEL=claude-sonnet-5-5  # 선택. 기본값은 claude-opus-5-5
DIDIMDOL_API_KEY=...                  # API 서버 인증 키 (G7 서버와 공유하는 긴 무작위 문자열)
```

| 선택 환경변수 | 용도 |
|---|---|
| `DIDIMDOL_DB` | 공고 DB 경로 (기본 `collector_data/postings.sqlite3`) |
| `DIDIMDOL_ALLOW_NO_AUTH=1` | 로컬 개발용. `DIDIMDOL_API_KEY`가 없어도 서버가 열려요. **운영 환경에서는 쓰지 마세요.** |

## 전체 흐름

```
[수집]   기관 채용 게시판 → 제목으로 1차 판정 → 상세 본문 + 첨부(PDF/HWP/HWPX/DOCX/ZIP) 텍스트
          → SQLite 이력 저장 (마감 공고도 보관, 텍스트 해시로 정정공고 감지)
                                             ▼
[Claude] 공고 → 직무별 요구 항목 {항목, 유형, 필수/우대, 수준 0~3, 6축, 원문 인용}
               + 직무기술서 NCS 분류 + 학부생 지원 가능 여부      (인용이 원문에 없으면 버림)
                                             ▼
[NCS]    직무기술서 NCS 분류 → 세분류 코드 → 분야 보완, 요건이 비면 능력단위를 기본 요건으로
                                             ▼
[사용자] 포트폴리오 업로드(스캔본·사진은 Claude OCR) → (Claude) 경험 카드 초안 → 사용자 확인 후 저장
         경험 카드 → (Claude 판정 또는 어휘 추정) 요구 항목별 근거 수준 0~3 + 인용
         주간 체크인: 6축 자기평가, 마일스톤, 투자 시간, 컨디션
                                             ▼
[코드]   육각형(목표선·근거·자기평가) → 자기평가×근거 2×2 → 갭 우선순위 → 다음 한 칸
         추천(지금 도전 / 준비하며 목표 / 자격 갖춘 뒤 목표) · 지표 12종
                                             ▼
[규칙+Claude] 피드백 유형(칭찬·격려·채찍질) 결정 → 코치 톤 문장 (검사에서 떨어지면 템플릿)
                                             ▼
[출력]   API JSON / HTML 리포트 (육각형, 추이선, 커버리지 막대, 다크 모드)
```

역할 분담 원칙:

- **숫자와 판단은 코드가 해요.** Claude는 원문에서 구조를 뽑거나 문장을 쓰는 데만 써요.
- Claude 출력은 모두 JSON 스키마(enum 포함)로 형식을 제한해요. 원문 인용은 코드로 확인하고, 원문에 없으면 버려요.

## 사용자 입력 구조

사이트의 기존 화면(자기상태표, 직무검사)은 예시일 뿐이에요. 입력은 아래 4계층으로 새로 설계했어요. 원칙은 두 가지예요.

- **한 번에 다 받지 않아요.** 기록이 쌓일수록 분석이 정교해져요.
- **AI는 초안만 만들어요.** 확정은 사용자가 해요.

| 계층 | 주기 | 내용 | 엔진에서 쓰는 곳 |
|---|---|---|---|
| L1 온보딩 | 1회, 5분 이내 | 학적 상태(재학·졸업예정·졸업), 관심 분야 1~3개, 지역, 주당 투자 시간, 코치 톤, 직무검사 성향 | 추천 필터·점수, 피드백 톤 |
| L2 목표 | 학기 단위 | 목표 공고와 직무, 또는 분야·기관 + 기한 | 요구 항목 → 육각형 목표선 |
| L3 경험 카드 | 수시 | 유형, 기간, 역할, 내가 한 행동, 도구, 결과, 배운 점 (직접 작성 / 파일 업로드 → AI 초안) | 근거 수준 0~3 |
| L4 주간 체크인 | **매주**, 2분 이내 | 6축 자기평가(지난주 값이 미리 채워짐), 마일스톤(완료·진행·보류와 사유), 투자 시간, 컨디션(선택) | 자기평가 점수, 실행 지표, 피드백 |

- **6축은 사용자가 바꿀 수 없어요.**
- **컨디션은 진로 점수에 쓰지 않아요.** 피드백 톤 조절, 숲 힐링(토닥토닥) 연결, 본인만 보는 추세에만 써요.
- 데이터 구조는 [models.py](didimdol_ai/models.py)에 있고, API 요청 스키마는 [api.py](didimdol_ai/api.py)에 있어요. 사용자 데이터는 G7이 저장해요.

## 6축 육각형과 계산 규칙

### 고정 6축 ([data/axes.json](data/axes.json))

| id | 축 | 근거 |
|---|---|---|
| `domain` | 전공 지식 | NCS 직무수행능력(지식) |
| `research` | 연구·실험 수행 | 기술능력 |
| `data` | 데이터 분석·도구 | 수리능력, 정보능력 |
| `problem` | 문제해결 | 문제해결능력 |
| `communication` | 소통·문서화 | 의사소통능력 |
| `collaboration` | 협업·자기관리 | 대인관계, 자기개발, 자원관리 |

- 축마다 1~5단계 **행동 기술 앵커(BARS)**가 있어요. 예: "실험 조건을 스스로 설계해 본 적 있다".
- 체크인 화면에서 이 앵커를 보고 자기평가를 해요.

### 근거 수준 (경험 카드 → 요구 항목)

| 수준 | 의미 | 예 |
|---|---|---|
| 0 | 없음 | 관련 기록 없음 |
| 1 | 접함 | 수업·강의로 배움 |
| 2 | 수행 | 주어진 과제를 직접 해 봄 |
| 3 | 주도 | 스스로 설계·판단해 결과를 냄 |

### 축마다 저장하는 세 가지 점수

1. **목표선:** 목표의 요구 항목 수준
2. **근거 점수:** 경험 카드에서 판정한 수준
3. **자기평가:** 체크인에서 사용자가 입력한 값

### 계산식 ([scoring.py](didimdol_ai/scoring.py), [planning.json](data/planning.json))

- **척도 환산:** `1 + 수준 × 4/3`. 0~3 수준을 육각형의 1~5로 바꿔요.
- **항목 가중치:** `중요도 × 출처 신뢰도 × 유형 가중치`

  | 요소 | 값 |
  |---|---|
  | 중요도 | 필수 1.0, 우대 0.5, 큐레이션 0.4. 기관·분야 목표는 공고 요구 빈도를 써요 |
  | 출처 신뢰도 | A 공고 본문 1.0, B 직무기술서 NCS 0.8, C NCS 큐레이션 0.5 |
  | 유형 가중치 | 태도 0.4, 나머지 1.0. NCS 직업기초능력 10개(의사소통능력, 수리능력 등)에는 0.4를 한 번 더 곱해요(`basic_competency_weight`). 모든 직무에 똑같이 붙는 일반 항목이라, 직무 고유 항목이 우선순위를 이끌게 하려는 거예요 |

- **축 점수:** 그 축에 연결된 항목들의 가중 평균이에요. **연결된 항목이 없는 축은 `None`(해당 없음)으로 비워 둬요.**
- **체크리스트:** 6축에 연결되지 않는 요구(자격증, 어학, 안전교육 등)는 육각형 밖에 체크리스트로 보여줘요.

### 자기평가 × 근거 2×2 → 방향의 종류

| | 근거 낮음 | 근거 높음 |
|---|---|---|
| **자기평가 높음** | `record_proof` 기록·증명. 먼저 카드로 기록하고, 없으면 증빙 만들기 | `maintain_expand` 유지·확장 |
| **자기평가 낮음** | `learn_experience` 학습·경험. 가장 작은 단계부터 | `confidence_expression` 자신감·표현. 자소서·면접 소재로 |

### 갭 우선순위

```
갭       = max(0, 요구 수준 − 근거 수준)
우선순위 = 갭 × 가중치 × 실현가능성 × (1 + 성향 보정, 최대 0.2)
```

- **실현가능성:** 이번 단계를 넘는 데 필요한 시간과 `남은 주 × 주당 시간`을 비교해요.
  - 단계 전환 예상 시간: 0→1 8시간, 1→2 20시간, 2→3 40시간
- **목표 조정 제안:** 필요한 시간이 남은 시간보다 많으면 `needs_adjustment = True`가 돼요. 이때 기한이나 목표선을 조정하자고 정직하게 제안해요.
- **도달 예상 주 수:** `projected_weeks_to_target`가 주간 추세로 계산해요.

## 공고 수집기 (`didimdol_ai/collector/`)

```
게시판 목록 → 제목으로 1차 판정(학사 인턴 후보만) → 상세 페이지 + 첨부 다운로드
→ 첨부 텍스트 추출 → 본문·첨부 전체로 지원 대상 다시 판정 → SQLite 이력 저장 → JSON 내보내기
```

| 파일 | 역할 |
|---|---|
| `adapters/kict.py` `kist.py` `kiom.py` `kribb.py` `kier.py` | 처음 만든 5개 기관 파서. KIER는 목록의 기간 칸이 "-"이면 제목에서 날짜를 읽어요 |
| `adapters/boardes.py` | 전자정부 표준 게시판(`board.es`)을 쓰는 KRISS(표준연), KFE(핵융합연), KIGAM(지질자원연). 표 모양과 div 모양 목록을 모두 읽어요 |
| `adapters/kaeri.py` `kimm.py` `kims.py` `krri.py` `kfri.py` | 원자력연, 기계연, 재료연, 철도연, 식품연 파서 |
| `adapters/base.py` | 어댑터 공통 인터페이스와 도우미 (아래 설명) |
| `http.py` | robots.txt 준수, 같은 사이트 요청 간격 2초, 파일 20MB 제한, 일반 User-Agent |

| `store.py` | 공고 이력 DB (아래 설명) |
| `runner.py` | 실행 순서 관리. 지원서·동의서 같은 양식 첨부(`양식`, `서식`, `위반사항`, `검토기준`, `확인서` 등)는 요구 항목이 없어서 내려받지 않아요. 기관 목록이 2회 연속 0건이면 게시판 구조가 바뀌었다고 경고해요 |

**어댑터 공통 도우미 (`base.py`)**

- `attachment_links`: 같은 파일을 가리키는 링크(파일명 링크와 '다운로드' 버튼)를 하나로 합쳐요. 파일명은 링크 글자, `download`/`title` 속성, 가까운 상위 요소 순서로 찾아요.
- `longest`: 같은 class가 여러 요소에 붙어 있으면 글이 가장 긴 요소를 본문으로 골라요.
- 기관을 추가하려면 어댑터 1개, `adapters/__init__.py` 등록, `institutes.json` 한 줄이 필요해요.

**수집 대상 기관 (`data/institutes.json`)**

| 상태 | 기관 |
|---|---|
| 수집 중 (13곳) | KICT, KIST, KIOM, KRIBB, KIER, KRISS, KFE, KIGAM, KAERI, KIMM, KIMS, KRRI, KFRI |
| 수집 금지 (`blocked`) | KRICT(화학연), 안전성평가연구소, 극지연구소 — robots.txt가 검색엔진 외 수집기를 모두 막아요 |
| 확인 필요 (`pending`) | KITECH(외부 채용 사이트), KASI(목록을 자바스크립트로 불러옴), ETRI·KARI·KBSI·WIKIM(채용 게시판 위치 확인 필요), KISTI·KERI·NSR(접속 실패) |

**마감일 보완 (`filters.py`)**

- 목록에 접수기간이 없는 기관(KRISS, KIGAM, KAERI, KIMS, KFRI 등)은 본문과 첨부에서 "접수기간 … ~ …", "원서접수 …" 같은 문구를 찾아 마감일을 채워요.
- 끝내 마감일을 알 수 없는 공고는 게시 후 60일이 지나면 마감으로 봐요. 그래야 오래된 공고가 추천에 남지 않아요.
- 날짜는 `2026-11-02`, `2026.11.02`, `26.11.02`, `2026년 11월 2일` 형식을 읽어요.

**조회수 제거 (`runner.py`의 `strip_volatile`)**

- 일부 게시판은 본문 영역에 조회수나 다운로드 횟수가 들어 있어요(KAERI, KIGAM, KFRI, KRISS).
- 그대로 두면 열 때마다 내용 해시가 바뀌어 정정공고로 잘못 판단하고, 비용이 드는 재분석까지 일어나요.
- 그래서 해시를 계산하기 전에 이런 숫자를 지워요.

**지원하는 첨부 형식 (`extract.py`)**

| 형식 | 방법 |
|---|---|
| PDF | pypdf |
| HWP 5.x | olefile + 레코드 파싱 |
| HWPX | XML |
| DOCX | XML |
| ZIP | 한글(cp949) 파일명 처리. 디스크에 풀지 않고 메모리에서 크기 제한을 두고 읽어요 |
| TXT | 그대로 읽어요 |

**판정 규칙 (`filters.py`)**

- **학사 인턴 판정:** 인턴, 학생연구원, 연수생, 체험형은 포함하고 박사후, 경력, 정규직, 안내문은 제외해요.
- **유형:** 연구, 행정, 체험형으로 나눠요.
- **지원 대상:** 재학, 졸업예정, 졸업으로 나눠요. "재학 또는 휴학 중이 **아닌** 자" 같은 부정 표현도 처리해요.
- **날짜 파싱:** 공백이 낀 날짜와 끝 연도가 빠진 기간(`2026.6.10.~6.24.`)도 읽어요.

**공고 이력 DB (`store.py`)**

- 테이블: `postings`, `attachments`, `extractions`, `runs`
- 마감 공고도 지우지 않아요. 기관·분야 목표의 요구 빈도 분석에 써요.
- 내용 해시(`content_hash`)로 정정공고를 감지하고 `revision`을 올려요.
- 재분석 판단은 텍스트 해시(`text_hash`)로 해요. 본문·첨부 텍스트가 바뀔 때만 Claude로 다시 분석해서, 날짜 표기만 바뀐 공고에는 비용을 쓰지 않아요.

```bash
python -m didimdol_ai.collector run [--institutes kist,kier] [--pages 2] [--no-attachments] [--interval 2]
python -m didimdol_ai.collector export --with-text --out collector_data/export.json   # --all: 제외 공고 포함
```

- 내보내기 형식은 사이트의 `/api/modules/sirsoft-jobfit/internships` 응답에 맞췄고, `targets`, `attachments`, `revision` 필드를 더했어요.

### 5. Claude OCR (`ocr.py`)

스캔한 PDF나 사진으로 올린 포트폴리오는 일반 텍스트 추출로 글이 나오지 않아요. 이런 파일은 Claude가 이미지를 보고 글자를 받아 적은 뒤, 그 글로 4번(카드 초안)을 진행해요.

| 항목 | 내용 |
|---|---|
| OCR을 쓰는 경우 | 이미지(PNG, JPG, WEBP, GIF)이거나, 일반 추출 결과가 200자 미만인 PDF(스캔본) |
| 전송 방식 | 이미지는 `image` 블록, PDF는 `document` 블록(base64). 한도는 이미지 1장 5MB, PDF 30MB |
| 출력 | JSON 스키마 `{text, legible, notes}`. 스트리밍으로 받아요 |
| 받아 적기 원칙 | 보이는 글자만 고치지 않고 옮겨요. 요약, 교정, 추측은 하지 않고, 읽을 수 없는 곳은 `[판독 불가]`로 써요. 표는 한 행을 한 줄로 옮겨요 |
| 개인정보 | 이름, 학교, 학번, 전화, 이메일, 주소는 받아 적을 때 `[이름]` 같은 자리표시로 바꾸고, 끝난 뒤 코드(`mask_pii`)로 한 번 더 가려요 |
| 검증 | 카드 초안의 근거 구절은 OCR로 받아 적은 글에 실제로 있어야 해요. 글자를 거의 못 읽으면 더 선명한 파일을 요청해요 |

- **주의:** 이미지 원본은 그대로 Claude로 전송돼요. 업로드 화면에서 이 점을 사용자에게 알려야 해요. 텍스트 파일은 이름과 학교를 보내지 않는데, 이미지는 그 원칙을 완전히 지킬 수 없어요.
- **실제 확인:** 가상 학생의 스캔 이미지에서 카드 4장이 나왔고 검증에서 떨어진 카드는 없었어요. 사용량은 입력 약 4,300토큰, 출력 약 1,700토큰이에요.

  - 대분류 2자리, 중분류 4자리, 소분류 6자리, 세분류 8자리
  - 능력단위는 `10자리_xxvN`, 요소는 `…vN.M` 형식이에요.
- **분야 연결:**
  - 대분류마다 디딤돌 8개 분야를 붙여요(예: 화학 → 화학생명).
  - 이름에 빅데이터나 인공지능이 들어가면 AI데이터 분야로도 표시해요.
  - 능력단위는 이름 키워드로 6축을 추정해요(휴리스틱, 멘토 검수 필요).

### 공고 연결 (`find_detail_codes`)

직무기술서에 적힌 NCS 분류 이름으로 세분류 코드를 찾아요. 아래 순서대로 시도해요.

1. 이름이 정확히 같으면 그 코드를 써요.
2. 같은 대분류 안에서 부분 일치하는 이름이 하나뿐이면 그 코드를 써요(예: "PR" → "PR/광고").
3. 세분류 칸이 "-"이면 소분류 아래 세분류 전체를 써요.

현재 NCS 분류가 적힌 직무 18개가 **모두** 연결됐어요.

### 추천에서 쓰는 곳

- 추천 이유에 "NCS 직무: 화학물질분석"처럼 직무명을 보여줘요.
- 공고에서 분야를 못 정한 직무는 NCS로 분야를 채워요.
- 공고에 구체적인 요건이 없는 직무는 해당 능력단위를 **기본 요구 항목**으로 써요(출처 C, 수준 1, 최대 8개).

python -m didimdol_ai.ncs build              # 원본 CSV → data/ncs_curated.json

## 공고 추천 (`recommend.py`)

```bash
python -m didimdol_ai recommend                        # 어휘 추정 (비용 0)
python -m didimdol_ai recommend --judge 2              # 상위 2개 직무는 Claude 카드 판정으로 다시 계산
python -m didimdol_ai recommend --include-closed --admin --top 10 --profile ... --cards ...
```

| 단계 | 내용 |
|---|---|
| 후보 | 분석된 공고의 모든 직무 (현재 346개) |
| 필터 | 대학원생 대상과 마감 공고는 빼요. 행정 직무는 `--admin`일 때만 포함해요 |
| 점수 | `0.45·분야 일치 + 0.40·준비도 + 0.15·성향 적합` |
| 버킷 | **지금 도전할 자리**: 준비도 0.7 이상이고 지금 지원 가능 / **준비하며 목표로 삼을 자리** / **자격을 갖춘 뒤 목표로 삼을 자리**: 예를 들어 졸업 후 지원 가능 |
| 다양성 | 같은 공고에서 최대 2개, 같은 기관에서 최대 3개 |
| 설명 | 분야 일치, 내 카드와 요구 항목의 연결(판정과 추정을 구분해 표시), NCS 직무, 준비할 것 최대 3개 |

**준비도 계산**

- 요구 항목마다 `min(내 근거 수준, 요구 수준) / 요구 수준`을 구해 가중 평균해요.
- 계산에서 빼는 항목:
  - 체크리스트 항목
  - NCS 직업기초능력 10개: 한 공고의 모든 직무에 똑같이 붙어 있어서예요. 이 능력들은 주간 리포트의 6축에서 따로 다뤄요.
- 태도 항목은 준비도에는 반영하지만 "준비할 것"에는 넣지 않아요.
- 공고에 구체 요건이 없어 준비도를 계산할 수 없는 직무(예: 전공만 적힌 KIMS 연수제안서)는 준비도 대체값 0.35(`unknown_readiness`)를 써요. 근거로 계산된 직무보다 앞서지 않게 하려는 거예요.

**어휘 추정 (Claude 없이 카드와 요구 항목 연결)**

- 낱말 단위 2글자 조각이 얼마나 겹치는지 봐요. 겹침 비율이 0.34 이상이면 연결해요.
- 잘못된 연결을 막는 장치:
  - "일반", "지식", "경험", "능력" 같은 흔한 말은 빼고 계산해요.
  - 겹치는 조각은 카드의 **같은 낱말 안**에서 나와야 해요. 그래서 "전기영동"과 "생화학"을 합쳐 "전기화학"으로 잘못 연결하지 않아요.
  - 겹침이 1조각뿐이면 연결하지 않아요.
  - 태도·의향 항목(예: "대학원 진학 관심")은 추정하지 않아요.
- 카드 수준은 카드 유형으로 정해요. 수업·독학·자격증은 1, 프로젝트·학부연구생·인턴은 2예요.
  - 2 이상인 카드에 "직접 설계", "주도", "팀장" 같은 표현이 있으면 3이에요.
- 추정이라 근사치예요. 정확하게 판정하려면 `--judge`나 `/v1/judge`를 쓰세요.

## 다음 한 칸 행동 (`actions.py`)

- 우선순위가 높은 갭부터 [action_templates.json](data/action_templates.json)에서 행동을 골라요.
  - 템플릿은 6축 × 단계 전환(0→1, 1→2, 2→3)과 자격증·도구용으로 나뉘어 있어요.
  - 예: 1→2 "공개 데이터로 미니 분석 프로젝트"
- 한 번에 **한 단계만** 제안하고, 한 주에 최대 3개까지 보여줘요.
- 태도 항목에는 행동을 제안하지 않아요.
- 같은 항목이 2주 이상 보류되면(`requirement_id` 기준) 30분짜리 **"작은 첫걸음"**으로 쪼개서 제안해요.

## 피드백 엔진 (`feedback.py`)

규칙이 피드백 유형과 근거를 정하고, 문장은 템플릿이나 Claude가 써요.

| 유형 | 트리거 예 |
|---|---|
| 칭찬 | 축 상승, 마일스톤 완료, 근거가 자기평가보다 높음("스스로 낮게 봤지만 근거는 충분해요") |
| 격려 | 정체, 외부 사유로 보류, 체크인 공백 뒤 복귀 |
| 채찍질(직설) | 자기평가가 근거보다 1.5 이상 높음, 같은 항목 반복 보류, 기한 4주 이내인데 격차가 큼 |

- **컨디션 2 이하:** 채찍질을 자동으로 빼고 격려로 바꾼 뒤, 숲 힐링(토닥토닥)을 제안해요.
- **개수와 정렬:** 한 주에 최대 2개예요. 코치 톤(칭찬형·균형형·직설형)이 우선순위를 정해요.
- **근거 표시:** 모든 피드백에 근거 데이터(`reason`)를 함께 보여줘요.
- **공백 처리:** 체크인을 거른 주는 공백으로만 표시해요. 벌점이나 압박 메시지는 없어요.

## 보안·개인정보·수집 윤리

- **API 키:**
  - `.env`에만 두고 코드, 로그, 다른 파일에는 남기지 않아요.
  - `.env`와 `collector_data/`는 깃에서 제외돼 있어요.
- **Claude로 보내는 개인정보:**
  - 이름과 학교는 보내지 않아요.
  - 이메일과 전화번호는 가린 뒤 보내요.
  - 컨디션 점수는 보내지 않아요.
- **비교 금지:**
  - 타인 비교 표현(다른 사람, 평균, 상위 %, 순위 등)을 정규식으로 검사해요.
  - 이 검사는 리포트 HTML, 피드백 문장, 시뮬레이션 전체에 적용돼요.
- **수집 윤리:**
  - robots.txt를 지키고, 같은 사이트에는 2초 간격으로 요청해요.
  - 공개 게시물만 수집하고 CAPTCHA는 우회하지 않아요.
  - 첨부 원본은 다시 배포하지 않아요. 화면에는 요약, 추출 결과, 원문 링크만 보여줘요.

## 알려진 한계

- **KICT 첨부는 받지 않아요.** 첨부가 JS로만 열리고, robots.txt가 다운로드 경로(`/boardDownload.es`)를 금지해요. 그래서 KICT 공고에는 제목과 기간만 있어요.
- **KRICT(한국화학연구원)는 수집하지 않아요.** robots.txt가 `Disallow: /`예요. `institutes.json`의 `blocked`에 기록해 뒀어요.
- **KIST·KRIBB의 robots.txt는 HTTP 400을 돌려줘요.** RFC 9309에 따라 "제한 없음"으로 처리하고, 실행할 때마다 그 사실을 출력해요.
- **PDF 글자 겹침:** PDF 일부는 같은 글자가 두 번 겹쳐 추출돼요(예: "자격요건자격요건"). 인용 검사에서 허용하도록 처리했어요.
- **NCS 데이터 범위:** 큐레이션 파일에는 코드와 이름만 있고, 능력단위의 수준과 정의는 없어요. 능력단위를 6축에 나누는 것도 키워드로 추정해요.
- **추천 연결은 근사치:** 카드와 요구 항목의 어휘 추정 연결은 근사치예요. 정확도를 Claude 판정과 비교해 측정한 적은 아직 없어요.
- **초기 가정값:** `axes.json`, `action_templates.json`, `planning.json`의 문구와 수치는 멘토 검수 전 초안이에요.
